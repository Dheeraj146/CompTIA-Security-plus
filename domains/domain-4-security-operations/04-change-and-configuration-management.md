# Change and Configuration Management

## Configuration Management

Configuration management keeps systems in an approved and documented state. It addresses baselines, changes, dependencies, versioning, and configuration drift.

## Change Management

A normal change should be requested, assessed for risk and impact, approved by the appropriate authority, scheduled, implemented, validated, documented, and reviewed.

### Emergency Changes

Emergency changes address urgent security or availability needs. They may use an expedited approval process but should still be documented and reviewed afterward.

## Configuration Drift

Drift occurs when a system moves away from its approved baseline because of manual changes, software updates, unauthorized modifications, or inconsistent deployment. Continuous configuration monitoring helps detect drift.

## Secure Deployment

Use hardened templates, standard images, infrastructure-as-code controls, version control, automated validation, and separation of duties where appropriate.

## Exam Focus

A baseline defines the expected secure configuration. Change management controls how deviations are introduced and tracked. Emergency changes are expedited, not exempt from accountability.
