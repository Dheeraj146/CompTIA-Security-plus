# Cloud Security Architecture

## Service Models

**IaaS** provides virtualized infrastructure; the customer manages more of the operating environment. **PaaS** provides a managed application platform; the provider manages more infrastructure. **SaaS** provides a complete application service; the provider manages most underlying components.

## Deployment Models

Public, private, hybrid, and community approaches differ in ownership, access, isolation, and operational responsibility.

## Shared Responsibility

Cloud security is divided between provider and customer. The exact boundary depends on the service model. Customers remain responsible for configuring their resources correctly, managing identities, protecting data, and understanding provider controls.

## Cloud Security Controls

Use strong identity controls, MFA, least privilege, secure APIs, encryption, key management, network segmentation, logging, configuration monitoring, vulnerability management, backups, and secure secret storage.

## Cloud-Specific Risks

Misconfigured storage, excessive permissions, exposed management interfaces, insecure APIs, stolen cloud credentials, weak tenant isolation, unmonitored services, and shadow cloud resources can create major exposure.

## Exam Focus

The more managed the service, the more infrastructure responsibility shifts to the provider, but secure configuration and identity management remain critical customer responsibilities.
